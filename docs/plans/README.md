# Implementation plans

Create a plan when work spans multiple components, changes a trust boundary, or cannot be safely completed in one focused pass.

```markdown
# Outcome
One observable result.

## Scope
Included and explicitly excluded work.

## Approach
Ordered implementation slices and affected boundaries.

## Verification
Commands, repository fixtures, expected evidence, and failure cases.

## Decisions or follow-ups
Durable decisions to record and intentionally deferred work.
```

Delete obsolete plans or mark their outcome. This directory is not a second backlog.
